What Is a Version Control System?
GIT 
Definition

A Version Control System (VCS) is a system that 
records changes made to files over time so that 
previous versions can be viewed or restored.

The uploaded lesson defines VCS as a system that
records file changes over time and enables 
collaboration, history tracking, and reverting to earlier versions.

Simple definition for students

VCS = A system that remembers the history of your project or folder 
or directory. 

Benefits of Version Control

The lesson identifies several important benefits: 
storing versions, mitigating code mismatch, 
parallel development, collaboration, and backup.

1. Version History
2. Collaboration
3. Backup
4. Parallel Development

What Is Source Code Management?
Definition

Source Code Management (SCM) is the process of 
tracking, managing, and controlling changes to source code.

The lesson describes SCM as a process for tracking, managing, and controlling source-code changes while supporting collaboration, history, and code integrity.

Simple definition

SCM = Managing the complete history and collaboration of source code


VCS vs SCM

A useful training explanation:

| Concept | Meaning                                                    |
| ------- | ---------------------------------------------------------- |
| VCS     | Tracks versions of files                                   |
| SCM     | Broader process of managing source code                    |
| Git     | A VCS tool                                                 |
| GitHub  | Platform for hosting/collaboration around Git repositories |


SCM Purpose

SCM helps with:

1. Tracking changes
2. Maintaining history
3. Conflict management
4. Branching

Types of Version Control Systems

Two important models:

1. Local VCS
2. Centralized VCS      many client and one server 
3. Distributed VCS      many client and one server (local repository as well as remote repository)

Git
Definition

Git is a distributed version control system used to track changes in files, particularly source code.

The lesson describes Git as a VCS for tracking changes and supporting multiple developers and parallel branches.

Key characteristics

Git:

tracks changes
maintains history
supports branches
supports merging
supports distributed development
allows collaboration
works locally
can synchronize with remote platforms

Git Commands — One by One
1. git config
Definition

git config is used to configure Git settings 
such as the developer's name and email address.

Git uses this information when creating commits.

Why do we need it?

When you create a commit, Git records:

Who made this change?

For example:

Author: Akash Kale
Email: akash@example.com
Syntax
git config <option>
1.1 Configure username

git config --global user.name "Akash Kale"

git config --global user.name "YourName"

Explanation
git
 ↓
config
 ↓
--global
 ↓
user.name
 ↓
"Akash Kale"

--global means the configuration applies to your Git user across repositories on that machine.

1.2 Configure email
git config --global user.email "akash@example.com"

git config --global user.email "youremailId@example.com"

Use the email associated with the account you intend to use for your Git hosting service when appropriate.

1.3 Check configuration
git config --global --list

Example output:

user.name=Akash Kale
user.email=akash@example.com

git init

Definition

git init initializes a new Git repository in the current directory.

Syntax
git init

Example

Create a project:

mkdir employee-app
cd employee-app

Then:

git init

Git creates a hidden:

.git

directory.

Your project becomes:

employee-app/
│
├── .git/
│
├── Employee.java
└── README.md

Important

.git is the directory where Git stores repository metadata and history.

git status

Definition

git status displays the current state of the Git repository.

Syntax

git status

Example

Suppose we create:

Employee.java

Run:

git status

Git may show:

Untracked files:

    Employee.java
What does "untracked" mean?

It means Git sees the file, 
but the file has not yet been added to the staging area.

After modification

Suppose Employee.java is already tracked and we modify it.

Run:

git status

You may see:

Changes not staged for commit:

    modified: Employee.java

git add .

Definition

git add moves changes from the working directory to the staging area.

Syntax

git add <filename>

Example

git add Employee.java

Now:

Working Directory
       |
       | git add
       ↓
Staging Area
Add multiple files

git add Employee.java Department.java

Add all changes

git add .

The . means the current directory and its contents.

git commit

Definition

git commit records the staged changes as a 
new snapshot in the local repository.

Syntax
git commit -m "commit message"

Example
git commit -m "Add employee class"

Workflow:

Employee.java
     ↓
git add
     ↓
Staging Area
     ↓
git commit
     ↓
Local Repository

Why commit messages matter

Bad:

git commit -m "changes"

Better:

git commit -m "Add employee validation"

Best practice:

Commit messages should clearly describe the change.

The lesson recommends frequent commits and descriptive commit messages.

git log

Definition

git log displays the commit history of the repository.

Syntax
git log

Example:

commit a12345
Author: Akash Kale
Date: ...

    Add employee class

commit b67890
Author: Akash Kale
Date: ...

    Create project structure
Short history

git log --oneline

Example:

a12345 Add employee validation
b67890 Add employee class
c45678 Initial commit

git diff

Definition

git diff shows changes between versions/states of files.

Example

Suppose the original code is:

System.out.println("Employee Application");

You change it to:

System.out.println("Employee Management System");

Run:

git diff

You may see a conceptual difference like:

- System.out.println("Employee Application");
+ System.out.println("Employee Management System");
Purpose

Before committing:

git status
git diff

This lets you review your changes.

git branch

Definition
git branch is like a pointer which hold more than one commits information. 

git branch is used to create, list, and manage branches.

List branches
git branch

Example:

* main
  feature-login
  feature-payment

* identifies the current branch.

Create a branch
git branch feature-login

This creates the branch but does not switch to it.

The lesson covers branch creation and listing using git branch.

git switch
Definition

git switch changes the current branch.

Syntax
git switch <branch-name>
Example
git switch feature-login

Now:

main
feature-login ← HEAD
Create and switch
git switch -c feature-login

This does two operations:

Create branch
     +
Switch branch

The lesson specifically presents git switch as the newer, more focused alternative for branch switching.

git checkout

git checkout is the traditional command that can be used to switch branches.

Switch branch
git checkout feature-login
Create + switch
git checkout -b feature-login

For new learners, I suggest teaching:

git switch

for branch operations, while also explaining checkout because it is common in existing Git documentation and projects.

git merge
Definition

git merge combines changes from one branch into the current branch.

Suppose:

main
  \
   feature-login

First go to main:

git switch main

Then:

git merge feature-login

Now the feature changes are integrated into main.

Important rule

The branch you are currently on is the branch that receives the merge.

git switch main
git merge feature-login

means:

feature-login
      ↓
     main

The lesson explicitly describes git merge as integrating independent development lines into the current branch.



Task on branch creation 
to view branch or check all branch names. 

--> git branch 
to create new branch 
--> git branch branch_name
to move or switch in another branch 
--> git checkout/switch branch_name 
Then in that or user defined branch do any task 
like create, delete or update file 
then 
--> git add .
--> git commit -m "commit message"
then switch to master branch 
--> git checkout/switch branch_name 
then view the difference between master and user defined branch 



git remote
Definition

git remote manages connections between your local repository and remote repositories.

Add remote
git remote add origin <repository-url>

Example:

git remote add origin https://github.com/username/employee-app.git
Check remote
git remote -v

Example:

origin  https://github.com/username/employee-app.git (fetch)
origin  https://github.com/username/employee-app.git (push)

Here:

origin

is the conventional name for the remote.

The lesson includes git remote add origin and git remote -v for connecting to and inspecting a remote repository.

git pull
Definition

git pull obtains changes from a remote repository and integrates them into your current branch.

REMOTE
   |
   | git pull
   ↓
LOCAL

Example:

git pull origin main
Why use it?

Suppose another developer pushed:

Developer B
    ↓
GitHub

You need those changes:

git pull origin main

The lesson describes git pull as fetching and merging remote changes.
